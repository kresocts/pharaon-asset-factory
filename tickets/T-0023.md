# T-0023 - Add immutable shape model binding and offline cache preflight

## Goal

Extend the T-0022 deterministic shape execution request with an explicit, immutable
binding to an operator-supplied Hunyuan3D 2.1 shape model manifest and an offline
verification of the existing external model cache. Add a canonical `shape preflight`
command that reuses the T-0021 job and path validation, resolves the explicit T-0022
backend, validates and binds one immutable model manifest using the existing T-0014
model-manifest and cache-verification implementation, verifies every required model
artifact already present in `MODEL_CACHE_DIR` by exact size and SHA-256, and emits a
deterministic, sanitized, versioned preflight envelope.

The command performs no writes, downloads, network access, heavy ML imports, GPU
initialization, or inference. Successful preflight removes the T-0022 blockers for
production model manifest not bound and model cache not verified, but still states that
execution is unsupported because the Hunyuan runtime/GPU executor has not yet been
implemented.

## Context

T-0021 introduced a strict, deterministic, offline shape-job contract. T-0022 added a
fixed backend registry and immutable execution request. T-0014 already provides a
canonical external-model manifest schema and offline plan/status/acquire/verify
commands. This ticket connects those existing boundaries without duplicating them and
without committing a production weight inventory. The real official Hunyuan shape
artifact manifest and acquisition procedure remain a later, independently reviewed
ticket.

## Acceptance criteria

1. T-0022 is `DONE` before work begins.
2. Existing `shape plan` and `shape prepare` behavior and regressions remain intact.
3. `python -m asset_pipeline.cli shape preflight --job JOB --backend BACKEND
   --model-manifest MANIFEST --json` is the canonical new command.
4. `--job`, `--backend`, and `--model-manifest` are mandatory; no hidden backend or
   manifest default exists.
5. The model cache root continues to use `MODEL_CACHE_DIR`, defaulting to `/models`.
6. `shape plan` and `shape prepare` remain model-cache-independent and non-mutating.
7. `shape preflight` is the only new command in this ticket.
8. Invalid CLI usage returns exit `64`.
9. T-0014 manifest parsing is hardened with a finite byte limit no larger than 2 MiB,
   exact `limit + 1` read-and-refuse behavior, UTF-8 enforcement, duplicate-key
   rejection at every object level, non-JSON constant rejection, and a stable
   `RecursionError` conversion without tracebacks.
10. Existing valid T-0014 fixture manifests remain valid and existing T-0014 CLI
    classifications/exit codes remain compatible.
11. A public read-only model-cache API accepts an explicit manifest path and cache
    root, reuses the existing parser/state/hashing/plan ID policy, and returns the
    same artifact identity, state counts, byte totals, file states, and
    success/not-verified decision as `models verify`.
12. The public read-only API performs no writes, directory creation, lock creation,
    cleanup, acquisition, or network request.
13. The Hunyuan shape-model binding policy is explicit and deterministic: artifact
    set `hunyuan3d-2.1-shape`; lowercase 40-hex immutable revision; exact
    `hunyuan3d-2.1-shape/<revision>` namespace; `https://huggingface.co` URLs with no
    credentials, fragment, or query; exact immutable repository/subdirectory/revision
    boundary; URL/file path equality; non-empty supported roles; and at least one
    `shape-config` and one `shape-weights` file.
14. Accepted roles are exactly `shape-config`, `shape-weights`, and `shape-auxiliary`.
15. No network lookup, model-hub API request, mutable reference, branch resolution, or
    automatic revision discovery occurs.
16. The emitted model binding is immutable, sorted, defensive-copy-safe, and excludes
    source URLs.
17. Successful preflight returns exit `0` and deterministic schema-versioned JSON with
    `SHAPE_MODEL_PREFLIGHT_READY`, `preparation_supported: true`,
    `model_binding_supported: true`, `model_cache_verified: true`,
    `execution_supported: false`, the normalized job, safe paths, backend descriptor,
    execution request, immutable model binding, sanitized cache-verification summary,
    and exactly the remaining blocker `GPU_EXECUTION_NOT_IMPLEMENTED`.
18. Repeated successful preflight runs with identical files, roots, and inputs produce
    byte-identical stdout.
19. Expected failures map to exit `2` (job/input policy, malformed/unknown backend,
    or model-binding refusal), `3` (runtime root, unsafe path, or invalid/oversized/
    unreadable model manifest), `4` (valid bound manifest with absent/partial/
    corrupted cache artifacts), `64` (invalid CLI usage), and `70` (sanitized
    unexpected internal/local I/O failure).
20. Expected errors emit parseable schema-versioned JSON with no tracebacks, raw
    signed/query URLs, environment dumps, secrets, or full exception internals.
21. `shape preflight` never creates or modifies output/workspace/model-cache files,
    creates locks, cleans stale partials, acquires artifacts, creates temporary files,
    opens a socket, calls model-hub APIs, initializes CUDA, or imports heavy runtime
    modules.
22. Focused tests cover manifest hardening, public read-only API parity and states,
    binding-policy refusals and immutability, CLI success/failure/determinism, no
    writes/network/cache-repair, fresh-process heavy-import proof, and T-0021/T-0022
    regressions.
23. Full repository tests, `run_ci.py`, repository validation, Phase 0 status, and PR
    whitespace checks remain green.
24. Documentation and ADR clearly state that cache verification is read-only, no
    real weights or inference are implemented, and future tickets are required for
    the independently reviewed official production manifest and Hunyuan runtime/GPU
    execution.
25. No Docker build/push, GHCR operation, runner startup, model download, cloud
    resource, paid API, GPU initialization, or inference occurs.
26. T-0023 ends in `REVIEW` with exactly one open non-draft PR and is not
    self-approved or merged.

## Implementation notes

The implementation reuses T-0014's manifest parser and cache-verification policy
rather than duplicating them. It hardens the existing manifest reader in
`docker/model_cache.py` and exposes a small public read-only verification function
that `models verify` delegates to. A new standard-library-only
`asset_pipeline/models.py` defines the strict Hunyuan shape binding policy and
immutable binding objects. `asset_pipeline/execution.py` builds the deterministic
preflight envelope, and `asset_pipeline/cli.py` adds the canonical command. All
fixtures are tiny and local; no production weights, real hashes, license acceptance,
or acquisition instructions are committed. The ticket transitions to `REVIEW` only
after all validation passes and is not self-approved or merged.
