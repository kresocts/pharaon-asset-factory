# T-0005 — Implement orchestrator state machine

## Goal

Implement a minimal orchestrator state machine that selects ready tickets and coordinates separate worker and reviewer runs from persistent GitHub state.

## Context

Once worker and reviewer contracts exist, orchestration can connect them without relying on a long-lived agent or hidden memory.

## Dependencies

T-0001 through T-0004 must be `DONE`.

## Allowed scope

Ticket readiness parsing, explicit state transitions, worker/reviewer dispatch interfaces, GitHub state reconciliation, bounded retry policy, documentation, and deterministic tests.

## Acceptance criteria

- Only dependency-satisfied `READY` tickets are eligible and selection is deterministic.
- State transitions are explicit, validated, persisted, and recoverable after restart.
- Worker and reviewer identities/roles remain separated.
- Infrastructure and implementation failures follow distinct bounded paths.
- Concurrent runs cannot claim the same ticket.
- No paid services or cloud resources can be invoked by default.

## Required tests

- Cover readiness, dependency ordering, invalid transitions, concurrent claims, restart recovery, bounded failures, and successful completion.
- Run the complete baseline CI suite.

## Out of scope

GPU provisioning, Hunyuan3D, image generation, final UI, and autonomous merge policy.

## Implementation notes

GitHub and repository state must remain authoritative. Keep the first state machine small enough to inspect and test exhaustively.
