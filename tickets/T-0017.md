# T-0017 - First controlled GHCR publication

## Goal

Perform exactly one controlled, SHA-only publication of the canonical
`ghcr.io/kresocts/pharaon-asset-factory` container from the exact current commit on
`main`, using the existing secure publishing workflow and the dedicated self-hosted
runner. Keep the ticket in `REVIEW` until the real publication and independent evidence
review succeed.

## Context

T-0015 defined the secure `workflow_dispatch`-only GHCR publishing workflow.
T-0016 validated the shared publisher implementation against a disposable
loopback-only registry without contacting GHCR. T-0017 is the first production
publication and is intentionally supervised: the preparation procedure is reviewed
independently in Stage A, and the single production publication occurs only after the
owner explicitly authorizes Stage B, approves the protected `ghcr-publish` environment,
and manually starts the dedicated runner.

The owner has configured:

- canonical image `ghcr.io/kresocts/pharaon-asset-factory`
- protected environment `ghcr-publish`
- required environment reviewer
- deployment restricted to `main`
- administrator bypass disabled
- full-length GitHub Action SHA enforcement enabled
- dedicated self-hosted runner `pharaon`
  - labels: `self-hosted`, `Windows`, `X64`, `pharaon-publisher`
  - installed at `D:\actions-runner`
  - manually started with `D:\actions-runner\run.cmd`
  - offline by default

The T-0015 and T-0016 security contracts are fixed.

## Dependencies

- T-0016 must be `DONE`.

## Allowed scope

This ticket, the operator runbook, the unexecuted evidence template, minimal
documentation changes only if needed, and executable publishing fixes only if a real
blocker is discovered during static review.

## Acceptance criteria

1. The first production publication originates from the exact current commit on `main`.
2. The workflow is manually triggered through `workflow_dispatch`.
3. `confirm_publish` is exactly `PUBLISH`.
4. `expected_sha` is the exact full 40-character `main` commit SHA.
5. `release_tag` is empty.
6. Only the immutable `sha-<full-commit-sha>` tag is requested.
7. The `ghcr-publish` environment is manually approved by the owner.
8. The dedicated runner is manually started only after the expected job is queued.
9. The runner is stopped immediately after the workflow finishes or fails.
10. The workflow completes with a valid `sha256` digest.
11. The published manifest is verified as Linux AMD64.
12. No `latest` or release tag is created.
13. Package visibility is observed and recorded but not modified automatically.
14. A failed publication is not automatically retried.
15. No model weights, paid services, or cloud build systems are used.
16. Evidence records the exact workflow run, commit, tag, digest, platform, and runner shutdown.
17. T-0017 remains REVIEW until the real publication and evidence review succeed.

## Out of scope

Starting the self-hosted runner automatically, installing the runner as a service,
modifying runner registration or labels, triggering the workflow before Stage A is
merged, bypassing the `ghcr-publish` environment, publishing from any branch except
`main`, publishing a release tag during the first publication, publishing `latest`,
`main`, `stable`, or any rolling tag, overwriting an existing tag, using a PAT, using
Docker Hub, using a cloud builder, using a GitHub-hosted or paid runner, renting a GPU,
downloading model weights, modifying package visibility automatically, retrying a
failed publication automatically, pruning Docker images or BuildKit cache, approving or
merging this ticket's own PR, or beginning another ticket.
