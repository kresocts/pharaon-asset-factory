# T-0024 - Pin official Hunyuan shape model inventory and provenance

## Goal

Create and independently verifiable evidence for one official, immutable, production
Hunyuan3D 2.1 shape-model manifest accepted by the T-0023 binding policy. Resolve the
official Hugging Face repository to one lowercase 40-hex immutable commit, identify the
exact minimal shape-runtime inventory required by the pinned Hunyuan source loader,
record exact byte sizes and SHA-256 identities without downloading the large model
blob, commit the canonical T-0014 schema-version-1 manifest, commit machine-readable
provenance and a human-readable evidence record, validate everything offline, and
record license/model-card facts without making a legal conclusion or authorizing
acquisition.

## Context

T-0023 implemented the immutable model binding and offline cache-preflight mechanism but
did not commit a real production inventory. T-0024 supplies the first official shape
inventory and provenance only. Model acquisition, cache population, GPU execution, and
inference remain future tickets.

## Acceptance criteria

1. T-0023 is `DONE` before work begins.
2. The official Hunyuan shape revision is resolved to a lowercase full 40-hex immutable
   commit and used consistently in every committed manifest URL, provenance identity,
   test expectation, and runtime instruction.
3. The production manifest is a valid T-0014 schema-version-1 manifest, parses with
   `docker.model_cache.parse_manifest`, and binds with
   `asset_pipeline.models.bind_parsed_model_manifest` for backend
   `hunyuan3d-2.1-shape`.
4. The manifest contains exactly `config.yaml` and `model.fp16.ckpt` with roles
   `shape-config` and `shape-weights`, sorted by path.
5. `config.yaml` identity is obtained from the immutable Hugging Face resolve URL by
   direct bounded retrieval and local SHA-256; `model.fp16.ckpt` identity is obtained
   from official immutable Hugging Face LFS/Xet metadata without requesting the weight
   body.
6. The machine-readable provenance schema-version-1 record matches the manifest,
   records official source metadata, exact file identities, source-loader references,
   license/model-card facts, and mandatory
   `operator_review_required: true`, `acquisition_authorized: false`, and
   `legal_conclusion: false`.
7. The human-readable evidence record contains the exact bounded request log, inventory
   table, loader evidence, license facts, and confirmations required by the ticket.
8. `validation/validate_production_shape_manifest.py` validates both committed files
   completely offline, emits `PRODUCTION_SHAPE_MANIFEST_VALID` and exit zero only when
   consistent, and emits a sanitized non-zero failure otherwise.
9. Focused tests cover manifest/provenance parsing/binding, identity consistency,
   immutable-reference rejection, license flags, source revision, offline
   plan/status/verify/preflight behavior, mutation rejection, and no-network/no-heavy
   import behavior.
10. Existing T-0014 through T-0023 tests remain green and repository metadata/CI/Phase 0
    checks pass.
11. No model payload is committed under `model-manifests/`, no cache is populated, and
    no Docker/GHCR/runner/GPU/cloud/paid/inference operation occurs.
12. T-0024 ends in `REVIEW` with exactly one open non-draft PR and is not self-approved
    or merged.

background removal; mesh or texture generation; packaging; API/server/cloud work; paid
services; automatic network behavior; license acceptance or legal conclusions.

## Implementation notes

The manifest is explicit and operator-supplied; no hidden default is added. The large
checkpoint identity is taken from official immutable Hugging Face LFS metadata only.
Normal runtime, tests, and validators remain offline. The ticket transitions to
`REVIEW` only after every required validation passes and is not self-approved or merged.
