# T-0018 - Normalize handled PowerShell native exit state

## Goal

Fix the stale `$LASTEXITCODE` failure observed in T-0017 run 31800647785 so that an
expected and successfully handled absent registry tag does not leave the PowerShell
process in failure, while preserving fail-closed behavior for existing tags and real
registry errors.

## Context

The first controlled T-0017 GHCR publication attempt failed before build or push at
the `Refuse existing requested tags` step. `docker manifest inspect` returned a
non-zero exit code for the absent SHA tag. The shared classifier correctly returned
`Absent`, but `$LASTEXITCODE` remained non-zero, and GitHub Actions used that stale
native exit state as the final step exit code.

Related incident: T-0017 failed run
https://github.com/kresocts/pharaon-asset-factory/actions/runs/31800647785

1. The stale `$LASTEXITCODE` failure is reproduced in a PowerShell 7 process-level test.

## Implementation notes

`Test-PublisherRegistryTagState` captures the native Docker exit code immediately and
returns `Absent` only after matching the existing narrow absence allowlist. For that
handled absence, the new explicit
`Reset-PublisherLastExitCodeAfterAbsence` helper assigns `$global:LASTEXITCODE = 0`
before returning control. Existing tags and every real error path return without that
normalization, so the workflow still fails closed. T-0019 will perform a separately
approved second controlled publication only after T-0018 is merged and independently
approved.
