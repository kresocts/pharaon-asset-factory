# T-0020 - Close Phase 1 ticket lifecycle

## Goal

Introduce a narrowly defined `SUPERSEDED` ticket status, use it to close the failed
T-0017 first GHCR publication attempt without falsely marking it successful, and update
current-status documentation so Phase 1 is explicitly complete and Phase 2 is the next
roadmap phase.

## Context

T-0017 remains `REVIEW` even though its first controlled GHCR publication attempt,
run 31800647785, failed before build or push. T-0018 fixed the stale PowerShell
`$LASTEXITCODE` defect observed in that failure. T-0019 then completed a separately
approved successful controlled SHA-only GHCR publication. Phase 1 is functionally
complete, but T-0017 has no accurate terminal lifecycle state.

The currently supported ticket statuses are `READY`, `IN_PROGRESS`, `REVIEW`,
`BLOCKED`, and `DONE`. No existing status accurately represents a failed ticket that
has been intentionally closed by later remediation/successor work while preserving its
failed evidence.

## Acceptance criteria

1. `SUPERSEDED` is accepted by the canonical ticket validator.
2. All previously valid statuses remain valid and unknown statuses remain rejected.
3. `tickets/README.md` defines `SUPERSEDED` as terminal, unsuccessful, non-runnable,
   and non-dependency-satisfying.
4. Only `DONE` continues to satisfy ticket dependencies.
5. Worker preparation refuses a `SUPERSEDED` ticket.
6. Orchestrator selection never selects a `SUPERSEDED` ticket.
7. A dependent ticket remains blocked when its dependency is `SUPERSEDED`.
8. T-0017 is `SUPERSEDED`, not `DONE`.
9. T-0017 acceptance criteria and failed evidence remain unchanged and authoritative.
10. T-0017 names T-0018 and T-0019 as remediation/successor history.
11. T-0018 and T-0019 remain `DONE`.
12. `PLAN.md` explicitly marks Phase 1 complete and leaves Phase 2 next.
13. Root and Docker documentation no longer present completed publication work as
    pending current work.
14. Documentation still states that weights, inference, and Asset Worker implementation
    are not completed by Phase 1.
15. Publishing workflow, publisher implementation, Docker runtime, and evidence records
    receive no executable or factual rewrite.
16. No runner, GHCR, Docker build/push, model download, cloud, paid, or Phase 2 operation
    occurs.
17. All focused tests, full tests, repository validation, Phase 0 status, and whitespace
    checks pass.
18. T-0020 ends in `REVIEW`, with one open PR, and is not self-approved or merged.

## Implementation notes

`SUPERSEDED` is terminal but unsuccessful. It means the ticket requires no further
implementation or review work, did not satisfy all of its own acceptance criteria,
preserves its original evidence and historical outcome, is not runnable by a worker,
is not selectable by the orchestrator, and does not satisfy another ticket's
dependency. The ticket body must identify the replacement/remediation ticket or
tickets and explain why supersession is justified. Only `DONE` satisfies dependencies.
This status is intended for exceptional lifecycle closeout, not as a shortcut around
failed acceptance criteria.

This ticket must not perform publication, build, download, inference, runner, cloud,
paid, or Phase 2 work. Transition T-0020 to `REVIEW` only after all validation passes;
do not set it to `DONE`, approve it, or merge it.
