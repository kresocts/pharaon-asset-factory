# T-0021 - Add deterministic shape-job contract and offline preflight

## Goal

Introduce a versioned, deterministic, provider-neutral shape job contract and a fully
offline preflight command for one reference-image-to-shape job. The component
validates and normalizes a job request, securely resolves input/output/workspace
paths, and emits a machine-readable execution plan. Real Hunyuan inference is
explicitly not implemented by this ticket.

## Context

Phase 1 is complete and Phase 2 - Asset worker is next. The repository already has a
containerized CUDA/Hunyuan dependency runtime and an external model-cache interface,
but there is no host-side asset-worker contract for a shape job. T-0021 establishes
that contract and an offline plan/preflight boundary so later Hunyuan shape-generation
work can consume a stable, deterministic interface. The implementation-agent `worker`
package is a different concern and remains unchanged.

## Acceptance criteria

1. A new `asset_pipeline` package exists and is distinct from the
   implementation-agent `worker` package.
2. `python -m asset_pipeline.cli shape plan --job JOB --json` is the canonical
   command.
3. Schema v1 accepts exactly the five documented fields and rejects missing, unknown,
   duplicate, malformed, incorrectly typed, or out-of-range values.
4. Job input is capped at 64 KiB and parsed deterministically.
5. Runtime roots use the existing `INPUT_DIR`, `OUTPUT_DIR`, and `WORKSPACE_DIR`
   conventions.
6. Absolute, traversal, drive-qualified, malformed, and escaping input paths are
   rejected.
7. Input symlinks and ancestor-symlink escapes are rejected.
8. Only non-empty PNG/JPEG/WebP regular files at or below 32 MiB are accepted, with
   extension/signature agreement.
9. Job-specific output/workspace targets are safely derived from `job_id`, remain
   contained, and must not already exist.
10. Planning makes no filesystem mutation and no network request.
11. A valid plan emits deterministic schema-versioned JSON with
    `execution_supported: false` and explicit future Hunyuan/GPU/model requirements.
12. Error classifications and exit codes are stable and documented.
13. Expected validation/policy failures do not emit tracebacks.
14. The command has no CUDA, PyTorch, Hunyuan, model-hub, Docker, runner, GHCR, cloud,
    or paid dependency.
15. Focused tests cover valid plans, determinism, schema failures, duplicate keys,
    size limits, image signatures, path traversal, symlinks, existing targets, no
    writes, no network, JSON errors, and CLI usage.
16. Full repository tests, metadata validation, Phase 0 status, and whitespace checks
    remain green.
17. Documentation and ADR clearly state that this is contract/preflight only and that
    real shape inference remains unimplemented.
18. T-0021 ends in `REVIEW` with one open non-draft PR and is not self-approved or
    merged.

## Implementation notes

The implementation is standard-library-only and performs no writes, directory
creation, temporary-file creation, lock creation, downloads, or network calls during
planning. It introduces `asset_pipeline` with separate contract, path-policy, and CLI
modules plus a package README. Stable exit codes are `0` valid plan, `2` invalid job
document or input-policy refusal, `3` invalid/missing runtime root or unsafe path,
`64` invalid CLI usage, and `70` unexpected internal error. The ticket transitions to
`REVIEW` only after all required validation passes; it is not self-approved or merged.
