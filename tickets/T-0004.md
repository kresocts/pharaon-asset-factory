# T-0004 — Define reviewer-agent workflow

## Goal

Specify and implement an independent, reproducible review workflow for ticket pull requests.

## Context

A fresh reviewer must evaluate the unchanged ticket criteria, diff, CI, and earlier feedback and emit a clear approval decision without modifying implementation.

## Dependencies

T-0001, T-0002, and T-0003 must be `DONE`.

## Allowed scope

Reviewer input/output contract, GitHub review integration, review-state transitions, documentation, fixtures, and workflow tests or simulations.

## Acceptance criteria

- Reviewer input includes the ticket, acceptance criteria, repository rules, PR diff, CI results, and prior review comments.
- Output is exactly an approval or a change request with precise actionable reasons.
- The reviewer cannot alter ticket acceptance criteria or silently modify code.
- Identity/permission controls prevent self-review by the implementation worker.
- Review failures remain distinguishable from implementation and infrastructure failures.

## Required tests

- Test approval, requested-change, missing-context, failing-CI, and self-review rejection scenarios.
- Run the complete baseline CI suite.

## Out of scope

Ticket selection, pull-request merging, application features, and cloud/GPU execution.

## Implementation notes

Review evidence should be sufficient for a later orchestrator run to resume without agent memory.
