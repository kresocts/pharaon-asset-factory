# T-0011 — PyTorch and Hunyuan dependency layer

## Goal

Extend the reproducible T-0010 CUDA/Python image with the pinned PyTorch and Hunyuan3D 2.1 software dependency layer, without model weights or compiled Hunyuan native rendering extensions.

## Context

T-0010 established the provider-neutral CUDA 12.4/Python 3.10 container, stable runtime paths, external `/models` cache, and CPU-safe diagnostics. Hunyuan3D 2.1's official tested baseline uses PyTorch 2.5.1 with CUDA 12.4. This ticket makes that dependency boundary reproducible and diagnosable before T-0012 compiles the custom rasterizer and DifferentiableRenderer.

## Dependencies

T-0010 must be `DONE`, preserving its pinned base image and runtime path contracts.

## Allowed scope

This ticket, the Docker dependency image layers and dependency manifests, CPU-safe health and smoke diagnostics, Docker policy and health tests, the minimum root and Docker documentation updates, architecture documentation, and a concise dependency-pinning ADR.

## Acceptance criteria

- [x] The Docker image contains the pinned T-0010 CUDA/Python base and a PyTorch stack compatible with Python 3.10 and CUDA 12.4.
- [x] Exact installed versions are deterministic: PyTorch 2.5.1, torchvision 0.20.1, and torchaudio 2.5.1.
- [x] The PyTorch stack is installed from the official `https://download.pytorch.org/whl/cu124` index and diagnostics detect an accidental CPU-only wheel.
- [x] Official Tencent Hunyuan3D 2.1 source is fetched at a documented immutable full commit SHA, checked out and verified during the build, and does not depend on mutable `main` state.
- [x] Hunyuan source is installed at `/opt/hunyuan3d`, separate from `/app` and `/models`, with its revision recorded in machine-readable image metadata and a runtime revision file.
- [x] The pinned upstream Hunyuan requirements are retained as evidence, mirror directives are handled explicitly, and runtime dependencies needed for later shape and texture work are installed reproducibly with any compatibility adjustment documented.
- [x] Representative dependency imports run deterministically without model downloads and report readiness for torch, transformers, diffusers, accelerate, trimesh, and numpy.
- [x] No Hunyuan model weights, Real-ESRGAN checkpoints, Hugging Face snapshots, or other inference assets are downloaded, copied, or embedded in the image.
- [x] Container build, startup, health diagnostics, and smoke tests perform no automatic model download and require no Hugging Face token.
- [x] Neither `hy3dpaint/custom_rasterizer` nor `hy3dpaint/DifferentiableRenderer` is compiled or installed in this ticket, and diagnostics report both absences as intentional.
- [x] Health diagnostics extend T-0010 behavior and distinguish Python/CUDA runtime, NVIDIA GPU visibility, PyTorch installation and CUDA build/runtime state, Hunyuan source/revision, representative dependency imports, intentionally missing native extensions, external model cache, and model-weight presence without downloading anything.
- [x] Non-strict CPU Docker health succeeds without NVIDIA GPU access, imports PyTorch, reports CUDA unavailability cleanly, reports `HUNYUAN_DEPENDENCIES_READY`, and never falsely claims full Hunyuan inference readiness.
- [x] Strict GPU Docker health uses PyTorch rather than only `nvidia-smi`, requires `torch.cuda.is_available()`, reports an NVIDIA device, allocates and operates on a small CUDA tensor, synchronizes, and succeeds on an available NVIDIA GPU.
- [x] The T-0010 external `/models` cache and `/app`, `/data/input`, `/data/output`, and `/workspace` path strategy remains unchanged.
- [x] OCI labels expose the image purpose, Hunyuan repository and commit, and pinned PyTorch version without credentials or host-specific values.
- [x] Docker layers are ordered so small Pharaon runtime-script changes do not force reinstalling PyTorch and Hunyuan dependencies; unnecessary apt, pip, and Git metadata caches are removed.
- [x] Dockerfile policy, CPU-mode health fixtures, native-extension boundary, no-download/model policy, and Python/PyTorch/Hunyuan version contracts have deterministic GPU-free automated tests.
- [x] A real Docker image build completes, and its exact command, duration, and resulting image size are recorded as ticket/PR evidence.
- [x] A real CPU container smoke test succeeds, and a real GPU PyTorch CUDA smoke test succeeds when the configured RTX 4060 Docker GPU remains available; unavailable GPU infrastructure is reported distinctly.
- [x] Existing baseline CI, Docker tests, repository metadata validation, Phase 0 readiness, and `git diff --check` remain green.
- [x] No secrets, credentials, paid services, cloud integrations, provider provisioning, or image publishing are introduced.

## Out of scope

Compiling or installing the Hunyuan custom rasterizer or DifferentiableRenderer, downloading model weights or inference assets, executing Hunyuan inference, T-0012 or later ticket work, a service or web UI, cloud/provider logic, paid APIs or resources, Hugging Face authentication, GHCR publishing, and autonomous approval or merge.

## Implementation notes

Use the official upstream installation guide as the compatibility source of truth. Pin Hunyuan to `82920d643c0dc2f7bfd7255f45f62d386edfe60c`, the official `main` revision resolved on 2026-08-12, and document the intentional upgrade procedure. Preserve the upstream requirements as immutable evidence while using explicit constraints or a sanitized manifest where needed for standard package sources and deterministic resolution. Health and smoke imports must set process-local no-download/offline safeguards and avoid importing modules with weight-fetching side effects. Transition this ticket to `REVIEW` only after implementation and required validation are complete; only an independent reviewer and merge workflow may set it to `DONE`.
