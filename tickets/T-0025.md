# T-0025 - Repeat bounded Hunyuan shape provenance capture

## Goal

Create one official, immutable, production Hunyuan3D 2.1 shape-model manifest and
complete provenance evidence that passes the existing T-0014 manifest parser and
T-0023 Hunyuan model-binding policy, identifies the exact minimal shape inventory,
records exact file sizes and SHA-256 identities, proves loader compatibility using
immutable source files and exact line ranges, records exact bounded network accounting
for the new T-0025 research session, and validates completely offline without
authorizing or performing acquisition.

## Context

T-0023 added an immutable binding policy and offline cache preflight but deliberately
left the real official Hunyuan shape inventory to a later independently reviewed
ticket. PR #22 (`T-0024`) attempted that inventory, but independent review rejected it
because one HTTP response byte count was not captured, exact immutable line ranges for
the loader flow in `pipelines.py` and `utils/utils.py` were not retained, and the
evidence/validator temporarily treated missing proof as acceptable.

T-0025 replaces the abandoned, unmerged PR #22 attempt. PR #22 remains closed and
unmerged; its branch is an audit/reference artifact only. T-0024 is not a dependency
because it was never merged into the repository. This ticket starts from current
`main`, uses a new explicitly authorized bounded research session, and produces
independently reviewable evidence without erasing or rewriting the history of PR #22.

## Acceptance criteria

1. The preflight prerequisites are confirmed before editing or networking:
   current `main`, fast-forward-only pull, clean tree, T-0023 `DONE`, PR #22 closed
   and unmerged, no `T-0024.md` on `main`, and no existing T-0025 branch/ticket/PR.
2. The branch is exactly `ticket/T-0025-production-shape-provenance-retry` from the
   recorded base SHA.
3. A purpose-built append-only request logger enforces at most 10 HTTPS requests and
   at most 2 MiB total response-body bytes, disables automatic redirects, counts every
   redirect hop, follows only validated official HTTPS hosts, sends no auth/cookie,
   disables ambient credentials, uses a 30-second timeout, performs no retry, streams
   with a hard byte ceiling, computes SHA-256 while reading, retains only permitted
   small bodies, and fails closed on oversized `Content-Length` or budget exhaustion.
4. No checkpoint/weight body, model cache population, Docker/GHCR/runner/GPU/cloud/
   paid/inference operation is performed.
5. The exact minimal shape inventory is
   `hunyuan3d-dit-v2-1/config.yaml` and
   `hunyuan3d-dit-v2-1/model.fp16.ckpt`.
6. The production manifest uses T-0014 schema version 1, an immutable lowercase
   40-hex model revision, the exact `hunyuan3d-2.1-shape/<revision>` namespace, and
   the exact two-file inventory with exact sizes and lowercase SHA-256 values.
7. Provenance records the immutable model and source revisions, exact per-file
   identity methods, exact loader source URLs and body SHA-256 values, exact positive
   line ranges, license/model-card metadata, immutable license URLs, the authoritative
   bounded request log with exact aggregate totals, and the fail-closed license gates.
8. The offline validator defensively parses provenance and manifest, binds the manifest
   through the existing policy, checks the exact inventory, consistency, immutable
   official URLs, Dockerfile source pin, loader line-range evidence, request
   accounting, and no model payload under `model-manifests/`.
9. All required tests pass with network access disabled or patched closed, including
   existing T-0014 through T-0023 regression tests.
10. T-0025 transitions to `REVIEW` only after all checks pass; exactly one non-draft
    PR targets `main`; the worker does not approve or merge.
