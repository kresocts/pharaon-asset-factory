# T-0010 — Base CUDA/Python Docker image

## Goal

Create the first Phase 1 implementation: a reproducible, provider-neutral NVIDIA CUDA and Python container foundation that later Hunyuan3D tickets can extend.

## Context

Phase 0 is complete. The GPU asset worker now needs a small, deterministic container layer with stable runtime paths and diagnostics before model code or dependencies are introduced. This ticket establishes only that base layer and does not claim that Hunyuan3D is available.

## Dependencies

T-0006 must be `DONE`, proving the Phase 0 worker/reviewer handoff and readiness check.

## Allowed scope

This ticket, Docker image files and documentation, a host-testable runtime health command, Docker-specific deterministic tests integrated with baseline CI, the minimum architecture overview update, and a concise container-runtime ADR.

## Acceptance criteria

- [ ] A reproducible Dockerfile exists for the GPU worker base image.
- [ ] The image uses a pinned official NVIDIA CUDA development base image and does not use an unbounded `latest` tag.
- [ ] Python 3.10 is explicitly installed and available inside the image.
- [ ] Stable runtime locations exist for application code, generated artifacts, inputs, optional working data, and future model cache.
- [ ] The future model cache is outside the application source path, configurable, and suitable for a volume or bind mount.
- [ ] A deterministic health command reports Python, platform/OS, configured paths, CUDA environment/runtime information, NVIDIA tool and GPU visibility, and PyTorch installation/CUDA state when applicable.
- [ ] Health diagnostics succeed without a GPU in non-strict mode, clearly report `GPU_NOT_AVAILABLE`, and do not falsely claim GPU readiness; an optional strict mode fails when a GPU is required but unavailable.
- [ ] The image builds without Hunyuan model weights, cloud credentials, paid services, private registries, or files outside this repository.
- [ ] The image and tracked Docker context contain no embedded secrets or automatic model downloads.
- [ ] Docker policy, health behavior, and default/overridden path configuration have deterministic automated tests that require neither Docker nor a paid GPU.
- [ ] Build, CPU smoke-test, future GPU run, health, mount, version-selection, and current-limitation instructions are documented.
- [ ] Existing baseline CI and repository metadata validation continue to pass.
- [ ] No Hunyuan-specific implementation is added beyond clearly documented future extension points.

## Required tests

- `python docker/health.py --json`

- `docker build --tag pharaon-asset-factory-gpu-base --file docker/Dockerfile .` when Docker is available
- `docker run --rm pharaon-asset-factory-gpu-base health --json` when Docker is available
- `git diff --check`

## Out of scope

Hunyuan3D code or dependencies, model weights or downloads, PyTorch and custom CUDA/rasterizer packages, texture or image-generation pipelines, web UI, provider integration, GPU rental or provisioning, paid APIs, persistent services, GHCR publishing, Kubernetes, and Compose.

## Implementation notes

Use a pinned official NVIDIA CUDA Ubuntu `devel` image because later native CUDA extensions need compiler tooling. Install Python 3.10 explicitly, run as a fixed non-root application user, keep model data outside `/app`, and make startup perform no network access or downloads. PyTorch is intentionally deferred to the next dependency-layer ticket; diagnostics must distinguish its absence from a broken installation.
