# T-0006 — Validate real worker/reviewer handoff

## Goal

Prove the Phase 0 development workflow with a real ephemeral worker, deterministic implementation evidence, one pull request, and an independent reviewer handoff.

## Context

This validation ticket is intentionally small and objectively reviewable. It is not a product feature and does not begin Phase 1. Its purpose is to exercise the repository's worker conventions against authoritative repository state before production application, container, GPU, model, or cloud work begins.

## Dependencies

T-0001 through T-0005 must all be `DONE`.

## Allowed scope

This ticket, a dependency-free Phase 0 status command under `validation/`, deterministic unit tests for that command, and the smallest useful root README update.

## Acceptance criteria

- A deterministic Phase 0 status command exists.
- The command reads canonical repository and ticket state rather than hardcoding success.
- The command reports T-0001 through T-0005 and each ticket's status.
- The command reports whether all Phase 0 dependencies are `DONE`.
- The command reports worker, reviewer, and orchestrator workflow test counts or equivalent measurable coverage.
- The command returns a non-zero exit code when Phase 0 is incomplete.
- Automated tests cover both `PHASE_0_READY` and `PHASE_0_INCOMPLETE` states and verify deterministic logical output.
- The implementation introduces no paid API, cloud resource, or GPU behavior.
- The canonical baseline CI command passes.
- The command's purpose, invocation, and READY/INCOMPLETE behavior are documented in the smallest appropriate place.

## Required tests

- `python -m unittest tests.test_phase0_status -v`
- `python -m unittest discover -s tests -v`
- `python validation/phase0_status.py`
- `python validation/validate_repository.py`
- `python validation/run_ci.py`
- `git diff --check`

## Out of scope

Phase 1 work, Docker, Hunyuan, image or asset generation, GPU execution, cloud resources, paid APIs, new orchestration or reviewer frameworks, LLM SDKs, autonomous approval, and merge behavior.

## Implementation notes

Use only the Python standard library and existing repository metadata parsing where practical. Keep output concise, deterministic, and human-readable. At implementation completion, transition this ticket to `REVIEW`; only an independent reviewer and the required merge workflow may justify `DONE`.
